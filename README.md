# 自动解压处理工具

## 首次部署

运行环境为 Windows、PowerShell 7、Python 3、7-Zip、Bandizip，以及音频处理所需的 FFmpeg/ffprobe。Python 部分使用标准库。

下载或克隆仓库后，先在项目目录创建本机配置：

```powershell
Copy-Item .\config.example.json .\config.json
New-Item -ItemType File -Path .\解压密码.txt
```

编辑 `config.json`，将 `plugins`、`naming` 和 `extraction.rj_password` 中的示例路径改为本机实际路径，并检查 Bandizip 安装位置。外置 WAV 转换器 `wav_to_mp3.bat` / `wav_to_mp3.ps1` 与 DLsite 重命名工具需要另外准备，不包含在本仓库内；使用完整流水线前须配置好 WAV 转换器。无需代理时保留 `naming.proxy_url` 为空，需要时填写本机代理地址。固定解压密码直接填写到 `解压密码.txt`，每行一个。

完成配置后双击 `启动界面.bat`。界面的“开始处理”会实际执行，并沿用成功后删除原包、源 WAV/FLAC 和 MP4 的现有规则；如需保留原包，将 `extraction.keep_original_archives` 设为 `true`。命令行省略 `-Run` 可先预演。

本机 `config.json`、`gui-settings.json`、密码文件、日志、输出、隔离目录、缓存及 `work` 中的备份均由 `.gitignore` 排除。仓库仅提供示例配置，不携带运行数据。

`extraction.max_expanded_size_gb` 当前设为 `0`，表示不限制预计展开体积；路径越界、文件数量以及普通 EXE/DLL 保护仍然启用。大型压缩包可能占满磁盘，运行时应观察剩余空间。

## 游戏和可执行文件保护

递归扫描不把普通 EXE/DLL 当作压缩包：PE 文件必须由 7-Zip 报告内嵌的 7z/RAR/ZIP 格式才进入解压队列，单纯能列出 PE 资源不算 SFX。直接拖入的普通 PE 也会拒绝并保留。游戏/软件目录含 EXE、DLL 或常见引擎资源特征时，整个作品跳过第二阶段的转换与删除，仍可进入名称补全。此规则偏保守，附带程序的音声作品也会受保护。同一最终目录的提交先核对内容：相同文件去重，独有文件合并，同路径不同内容保留双方并记录冲突。

旧版已误删游戏程序的输出不能通过完成标记自动修复；请保留原始压缩包，使用空输出目录重新解压恢复，不要依赖旧输出的续跑标记。

## 第三阶段：作品名称补全

在线查询优先使用与外置工具一致的 `https://www.dlsite.com/maniax/api/=/product.json?workno=RJxxxxxxxx&locale=zh_cn` 商品接口，语言沿用外置配置；校验返回的 `workno` 与标题后命名。只有接口返回空结果或 404 才尝试下述展示页兜底。因此展示页 404 的特典作品仍可获取正式标题。用户已通过外置软件改名时，仅接纳同一父目录内与元数据生成名称完全一致的目录，并修复本次结果清单和续跑映射。

解压成功后的清理统一识别 `.part1.exe + .part2.rar`、RAR part 分卷及 `.7z.001/.zip.001`。旧版本遗留的后续卷，仅在同组展开目录中存在含首卷名称、大小和完成时间的标记且首卷已不存在时清理；没有完成证据则保留。独立清理空的同 RJ 包装子目录（含隐藏文件的目录不算空），不依赖包装层折叠开关，不删除最终作品根目录或普通空音频目录。外层原压缩包默认在整组解压并提交成功后删除；任一内层包或提交失败时保留整组原包。设置 `extraction.keep_original_archives: true` 可保留外层原包。

界面“开始处理”依次执行递归解压、文件处理、作品名称补全。第三阶段只处理本次结果清单中的作品根目录，不启动外置重命名 EXE、不生成图标、不修改内部文件名。

默认只读复用配置中指定的 DLsite 重命名工具 `cache.db` 与其 `config.json`，按 `RJ号 作品标题 (CV 声优)` 补全名称。支持模板字段 `rjcode`、`work_name`、`cv_list_str`、`maker_name`；RJ号始终保留在开头。缓存未命中时按完整 RJ 号请求 DLsite 官方作品页，校验 canonical 地址编号及作品标题；不通过搜索结果猜测标题。在线结果缓存于本工具 `work/naming_metadata.json`，不写外置数据库。通过 `naming.online_fallback` 和 `online_timeout_seconds` 控制。404、超时、身份不一致、模板不支持、名称过长或目标冲突时保留原目录并记录待补全，前两阶段成果不受影响。

开关和数据源在本工具 `config.json` 的 `naming` 节。日志为 `logs/naming_*.jsonl`，新旧路径写入本次 `work/pipeline_results/extract_*.json`。可使用 PowerShell 7 单独重试第三阶段：

```powershell
pwsh -NoProfile -File .\rename-stage.ps1 -ResultFile "本次结果JSON的绝对路径"
```

输出父目录的 `.rj-name-map.json` 保存原始压缩包路径、大小、修改时间及本批作品的最终路径。再次拖入原包时，只有来源指纹全部一致且全部输出目录仍存在，才跳过重复解压；多作品套包会恢复整批作品清单。不要随意删除该映射文件。它不是文件内容完整性校验；手动移动作品目录后需要重新核对结果。

完整设计说明见 [`docs/项目设计文档.md`](docs/项目设计文档.md)。

用于手动拖入压缩包或目录后递归解压、处理文件并补全作品名称。当前主程序为 PowerShell 7，作品元数据查询与名称补全使用 Python 3；没有启用下载目录自动监控。


## 解压完成后的原包与包装层清理（2026-10-15）

默认启用“成功后删除原包”。只有当前解压任务中所有内层包处理完成、内容成功提交到最终目录且没有冲突时，才删除外层原包、内层包和对应全部分卷。任一步失败时保留该任务的原包与失败现场；其他成功的并行任务可正常收尾。删除前再次核对文件大小与修改时间，任务期间变化的原包不删除。

此规则不依赖 RJ 前缀：纯数字名称、普通名称、无扩展名、外层无编号但内层有编号、全程无编号的包均记录最终目录。没有 RJ 的作品在名称补全阶段直接保留目录名称。若解压目录与原文件路径相同，使用 `_extracted` 目录避免冲突。

同一最终目录已存在时，先在独立目录展开，再预检全部相对路径：大小与 SHA-256 相同的文件去重，独有文件合并，同路径不同内容保留双方并记录失败。不会仅凭相同编号删除第二份内容。解压失败临时目录保留。

整组成功后，自底向上清理本次登记的包装目录与其中只剩 `.extract_complete*.json` 的子目录；必要完成信息先写入 JSONL 日志，正式作品根目录始终保留。包装层中仍有附件或未知内容时保留并列出路径。遇到链接目录保留现场。此步骤不对音频、图片、台本等作品内容另做去重。

流水线调用 WAV 转换器时关闭同级目录自动补漏，只处理明确传入的成功作品。最终有解压失败时返回 2，名称补全未完成时返回对应代码，只有全部阶段成功才显示“一键流水线全部完成”。

## 图形界面

界面使用单窗口工作台：顶部选择输出位置并展示“递归解压 → 文件处理 → 作品命名”三个阶段；左侧管理输入，右侧保留实时日志，底部固定结果、耗时和开始／停止按钮。左右区域可以拖动分隔条调整宽度，输入列表显示文件名与父目录，选中后可查看完整路径。

“打开输出”在指定位置模式下打开输出根目录；原地址模式下打开选中输入所在目录。底部直接展示当前原包、源音频及 MP4 处理规则，“查看处理规则”可展开完整说明。它们读取现有配置，不修改处理规则。

解压阶段显示的是“已结束”的分组数，包含失败分组，不等同于成功作品数。进入文件处理和命名阶段后使用动态进度提示；只有流水线退出代码为 0 时才显示整批完成。部分失败、名称待补全和主动停止都会保留各阶段及最终状态，直到下一次开始。处理中不能修改输入或清空窗口日志。“停止”仍立即终止本次进程及其子进程。

界面布局位于 `src/extract-gui-layout.ps1`，阶段展示位于 `src/extract-gui-state.ps1`。执行 `pwsh -Sta -NoProfile -File .\extract-gui.ps1 -StartupTest` 可用临时模拟工作进程验证界面，不会处理真实压缩包；加 `-ScreenshotPath "绝对图片路径.png"` 可保存原生窗口渲染图。

双击 `启动界面.bat` 打开解压界面。可以拖入单个或多个文件/文件夹，选择“解压到原地址”或指定统一输出文件夹。

界面为单一的“开始处理”工作流，点击后直接执行“递归解压 → 文件处理 → 作品名称补全”。解压退出代码为 `2` 且存在有效结果目录时，成功作品继续处理，失败项保留在清单中；异常退出或缺失、损坏的并行结果清单会阻止后续阶段。界面默认选择“解压到指定文件夹”，用户选定后立即将路径保存到 `gui-settings.json`，下次启动自动恢复。需要预演时使用命令行，不传 `-Run`。

## 当前接入的处理插件

- DLsite 重命名工具：主流水线只读复用其缓存与配置进行名称补全，路径由 `config.json` 指定。
- 外置 `wav_to_mp3.bat` / `wav_to_mp3.ps1`：递归 WAV 转 MP3、完整性校验和日志，路径由 `config.json` 指定。

旧入口 `process.ps1` 保留“打开外置重命名工具 → 文件处理”的兼容流程，与界面的三阶段流水线不同。

音频处理对 WAV 和 FLAC 使用同样的成功后删除规则：优先采用作品自带的原生 MP3，不要求原生 MP3 达到 320 kbps，但必须能读取且与源音频时长匹配。找不到有效原生 MP3 时，WAV 调用既有外置插件，FLAC 由本工具转换为 320 kbps MP3；确认 MP3 有效后永久删除对应源音频，转换或校验失败时保留。FLAC 删除前还会完整解码校验源文件及目标 MP3。

文件处理层还会递归查找每部作品内的 `.mp4` 文件并永久删除。预演模式只显示待删除清单，不修改文件。

如果作品同时存在原生 `MP3軽量版` 和由 WAV 后转得到的普通本篇 MP3，系统优先保留原生轻量版。判断以目录版本语义和整组音频为单位，使用曲目数量、时长集合、轨道编号和一对一覆盖进行匹配，文件名只是辅助信号，不要求完全相同。`SEなし`、`BGMなし`、特典等独立变体不作为普通本篇的重复项删除。

原生 MP3 匹配不要求 WAV/FLAC 与 MP3 位于同一目录。处理器以整部作品建立索引，忽略 `WAV/FLAC/MP3` 格式目录，比较多层父目录，并识别有无效果音、`SE/SFX`、有无 BGM、音声-only 等版本标签。路径版本明确冲突或多个候选同分时不认定为原生配对。

文件名不一致时，处理器还会比较曲目编号、移除版本/音质标签后的核心名称和音频时长。最高候选必须达到最低置信度，并至少领先第二候选60分；低置信度或歧义情况一律不采用原生 MP3。

处理器先按 `RJ12345678` 目录划分独立作品。某部作品完全没有任何 MP3 文件时，该作品的全部 WAV/FLAC 直接进入 320 kbps 转换队列，不运行复杂匹配；不同 RJ 作品之间绝不共享 MP3 候选。

## 解压阶段

纯数字压缩包名称（例如 `01719814.7zkkk`、`01719814.7z.001` 或 `01719814 (1).7zkkk`）会统一识别为 `RJ01719814`，用于界面项目计数、串行分组、密码候选和最终目录。只接受完整的数字文件名主体，不从标题中的零散数字猜测编号。数字套包包含多个作品时，各内层作品仍按自己的 RJ 编号提交。

整批解压成功后，若数字包装目录只剩完成标记和 TXT/NFO/URL 附件，会整体保存到本工具 `quarantine/packaging_directories/日期/`，并记录原路径、目标路径和文件校验值。附件不删除；含媒体、未处理压缩包、未知目录或链接的包装层保留原位。

把单个或多个压缩包/文件夹同时拖到界面后，点击“开始处理”即直接执行完整工作流。支持 ZIP、RAR、7Z、常见分卷入口、EXE 自解压包和可根据文件头识别的无后缀文件。当前配置使用 7-Zip 进行安全预检、Bandizip 实际解压；EXE 自解压包只作为压缩数据读取，绝不执行。

实际解压：

```powershell
pwsh -File .\extract.ps1 "G:\下载目录" -Run

# 一键流水线默认同时解压 4 个不同 RJ；可按 SSD 性能调整（1-8）
pwsh -File .\processing-pipeline.ps1 -Run -MaxParallelProjects 4 "G:\下载目录\RJ00000001.zip" "G:\下载目录\RJ00000002.zip"
```

固定密码保存在 `解压密码.txt`，每行填写一个。密码不会写入普通日志。原始压缩包默认在整组解压和提交成功后删除；失败原包与现场保留以便检查。

重复套包会持续递归解压，直到新输出中不再出现压缩包。内层包在其所在目录旁展开，保留作品目录结构。为防止恶意或异常压缩包无限展开，安全上限为30层；达到上限仍有压缩包时，任务会报错并列为未完成。

预演使用快速目录检查，不完整读取大型压缩数据，也不删除原包。正式执行时，原包、中间包及分卷的删除统一延后到整组解压和最终提交成功之后。同名输出通过独立暂存目录预检与归并；有内容冲突时保留原包和现场。暂存目录只用于提交前核对，成功后清除空包装层，不作为额外作品目录留下。

当外层压缩包文件名只有 7–8 位作品数字（例如 `01673643.7z` 或 `1700447.99`）时，系统会自动补全为 8 位 `RJ` 号，同时生成大小写 RJ 解压密码候选和最终 RJ 目录名。对 `.7zkkk`、`.99` 等未知或伪装扩展名，扫描器会检查真实文件头，识别 7z、ZIP、RAR、GZip 和 PE/SFX 包。

用户直接拖入的每个文件都无条件作为初始压缩包处理，不再由扩展名或文件头预先排除；如果它实际不是压缩包，由 7-Zip 明确报错并计入失败。只有当输入是文件夹时，对其内部文件的递归扫描才继续使用扩展名和文件头识别，避免把普通作品文件全部当成压缩包。

正式执行时，直接拖入的无扩展名文件会根据真实文件头补上 `.7z`、`.zip`、`.rar`、`.gz` 或 `.exe`，避免原文件与同名输出目录冲突。递归扫描会排除 DOCX、XLSX、PPTX、OpenDocument、EPUB、APK 和 JAR 等 ZIP 容器文件，不将它们当成内层作品包。

`.part1.r/.part2.r` 和 `.part1.e/.part2.r` 等被截断扩展名的外层或内层分卷，会按真实文件头补全为 `.rar/.exe`。同组 part 分卷只将第 1 卷放入队列；即使第 1 卷已经展开或带有完成标记，第 2 卷及后续卷也绝不作为独立压缩包测试。

ZIP 文件名默认使用 `extraction.zip_filename_code_page = 932` 读取日文 Shift-JIS/CP932 名称，该参数同时用于密码测试、安全清单和正式解压，避免日文 ZIP 文件名变成乱码。

密码候选顺序为：文件名和父路径中出现的所有完整 RJ 号大小写 → 纯 7–8 位数字文件名补全的 RJ 号 → 本地缓存和 DLsite 模糊补全候选 → `解压密码.txt` 固定密码。文件名直接提取不依赖网络或缓存。

当路径中可识别完整 RJ 号时，最终作品统一提交到输出根目录下的 `RJ12345678` 文件夹。只有单一子目录的作品标题包装层会被剥离，`_temp` 等解压工作目录在成功提交后清理。

外层压缩包同时包含多个内层 RJ 包时，每个内层包以自身文件名中的 RJ 号建立独立最终目录，不继承外层包的 RJ 号。例如 `RJ01699926.rar` 内同时出现 `RJ01699926.zip` 与 `RJ01701292.zip`，会分别提交到 `RJ01699926` 和 `RJ01701292`，避免互相覆盖或触发“最终 RJ 目录已存在”。

压缩包路径中包含 RJ 号时，它也会自动作为密码尝试，并同时生成大写 `RJ` 与小写 `rj` 形式。号码显示不全时，程序优先查询 DLsite 重命名插件的本地 `cache.db`；本地结果无法确定时，再使用号码片段搜索 DLsite。只会发送 RJ 号码片段，不会发送本地路径或固定密码。

预演处理计划：

```powershell
pwsh -File .\process.ps1 "G:\待处理的父目录"
```

实际执行（会先打开重命名工具，关闭后继续转换音频）：

```powershell
pwsh -File .\process.ps1 "G:\待处理的父目录" -Run
```

跳过重命名、仅执行 WAV 转换：

```powershell
pwsh -File .\process.ps1 "G:\待处理的父目录" -Run -SkipRenamer
```

## 安全原则

预演模式不修改文件。实际执行时，只有目标 MP3 已存在并且通过格式与时长校验后，才永久删除对应 WAV/FLAC。目录清理以处理前的文件快照为准：只有原本仅含 WAV/FLAC 的目录，才能在音频全部成功处理后删除；原本存在其他文件时，该目录始终保留。RJ 作品根目录永远保留。

该行为沿用 `processing.delete_empty_wav_directories` 控制，当前为 `true`，同时适用于 WAV 和 FLAC。纯无损音频版本目录在其文件全部成功匹配或转换后，可以删除空文件夹。

例外沿用 `processing.preserve_wav_directories_when_work_has_no_mp3` 控制，当前为 `true`。如果整部作品在处理前完全没有 MP3，则该作品所有原始 WAV/FLAC 目录都加入保护名单。转换成功后删除源音频，保留原目录及其中新生成的 MP3。
